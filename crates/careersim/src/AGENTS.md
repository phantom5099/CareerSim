# AGENTS.md — crates/careersim/src

> 本规则覆盖 `src/*.rs` 与其子目录。子目录中的 `AGENTS.md` 只补充对应模块的边界，不重复本文件的通用规则。

## 1. 文件布局

- 使用 Rust 2018+ 的模块布局。模块入口使用 `foo.rs`，子模块使用 `foo/bar.rs`，不创建 `mod.rs`。
- `foo.rs` 与 `foo/` 属于同一个逻辑模块。模块级规则写在本文件或 `foo/AGENTS.md`，不能依赖把规则文件放在 `foo.rs` 旁边来获得子目录同级作用域。
- 模块入口文件只负责声明子模块、聚合公开类型和构造工厂。业务实现放在对应子模块文件中。
- 公开类型只从拥有模块聚合导出。消费方直接引用拥有者的类型，不在其他模块复制定义。

## 2. 分层边界

- `http` 只负责 HTTP 提取、鉴权、请求校验、响应序列化和路由装配。业务操作调用 service 或公开端口，不直接调用 PostgreSQL 适配器。
- service 接收业务输入，完成边界校验和用例编排，再转换为 store 可接受的 `Record`。
- store 接收 `Record`、实体和值对象，负责持久化端口和适配器，不依赖 HTTP 类型。
- HTTP 请求体、查询参数和路径参数使用 `*Request`，响应使用 `*Response`。service 输入使用 `*Input`，持久化写入使用 `Create*Record` 或 `Update*Record`，查询聚合使用 `*View` 或明确的 `*Details`。
- 领域实体、值对象和领域错误保留业务名称。不要用 `Dto`、`Command`、泛化的 `Request` 或 `New*` 代替层间语义。
- `pipeline` 只能包含纯领域计算和校验，不读取环境、不访问数据库、不执行网络 I/O。
- `agent` 负责会话事件、上下文投影、回合和工具循环。当前投递流程位置由 `application` 的 `stage_position` 保存，事件中的阶段字段用于历史与投影。
- `llm` 只提供模型端口、供应商配置和适配器。具体模型客户端不进入业务 service 或存储层。
- `store` 只解释事件信封和存储状态，不解释事件业务内容。事件语义由 `agent` 负责。

## 3. 依赖与可见性

- 依赖方向遵守 `http → service → store`。适配器只能在组合根或拥有模块的工厂中装配。
- `account`、`catalog`、`resume`、`application` 的 PostgreSQL 实现保持 `pub(crate)`，通过模块工厂注入。
- 默认使用私有项，crate 内共享使用 `pub(crate)`，只有跨 crate 的稳定契约才使用 `pub`。
- 不为解决双向依赖新增 `common`、`shared` 或 `util` 模块。先重划边界或抽取拥有明确职责的 trait。

## 4. 输入、错误与序列化

- 每个层间边界只保留一套同义输入或输出类型。类型移动时同步更新所有真实调用方、测试替身和聚合导出。
- 驱动和 SDK 错误必须在边界转换为本模块错误。公开签名不得泄漏 `sqlx` 或供应商 SDK 类型。
- 对外 DTO 使用 `camelCase`。事件信封由 store 分配 `v`、`seq`、`at`，调用方不构造。
- 事件版本变化必须考虑旧数据读取。事件枚举使用内部 `type` 标签，事件字段保持 `snake_case`。
- 生产路径不使用 `unwrap`、`expect`、`panic`、`todo` 或 `unimplemented`。

## 5. 异步、观测与敏感数据

- 不在 async 上下文执行阻塞 I/O。跨 await 的互斥使用 Tokio 锁，短临界区才使用标准库锁。
- 模型和工具调用必须接收取消令牌。取消写入 `Interrupted` 终态，未执行工具调用写入 `aborted` 结果。
- HTTP、回合、模型、工具、service 和存储边界保留结构化 tracing 上下文，成功、失败、取消和冲突路径都要有可检索结果。
- 密码、令牌、连接串、提示词、简历正文、请求体和工具原始参数不得进入日志或指标标签。指标标签只使用受控低基数值。

## 6. 测试与清理

- 模块单测放在对应模块的 `tests.rs`，只有极小纯函数才在源文件内写测试模块。
- 测试替身只在 `cfg(test)` 下编译。跨模块装配放在 `src/testing.rs`，模块专用替身就近放置。
- 测试验证可观察行为、错误类型、事件序列和副作用，不验证源码布局或类型是否存在。
- 冗余代码清理遵循仓库根 `AGENTS.md` §4.2，复核证据遵循 `docs/review.md` 的冗余代码检查。

## 7. 入口文件职责

- `app.rs` 是组合根，负责配置、连接池、迁移、适配器、路由和退出信号装配。
- `config.rs` 是唯一的环境变量读取边界。业务模块不得自行读取 `std::env`。
- `lib.rs` 只声明模块、导出稳定入口和提供服务工厂。`main.rs` 只负责进程启动、错误脱敏和退出码。
- `error.rs` 放跨启动边界的错误链工具，`telemetry.rs` 集中初始化观测，`testing.rs` 只提供测试装配。
